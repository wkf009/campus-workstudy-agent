# 补充规约：勤工俭学管理系统

## 一、非功能性需求

### 1. 安全性
- 用户密码采用 BCrypt 加密存储，禁止明文传输
- 采用 JWT（JSON Web Token）无状态认证，Token 过期时间默认 24 小时
- 接口按角色分级鉴权：
  - `/api/admin/**` 仅超级管理员可访问
  - `/api/department/**` 部门管理员及以上可访问
  - `/api/auth/**` 公开访问
- CORS 跨域限制在生产环境收敛为指定域名

### 2. 可用性
- 系统支持 Docker Compose 一键部署，减少环境配置成本
- 前端 Nginx 反向代理，前后端分离部署
- 数据库采用 Docker Volume 持久化，防止数据丢失

### 3. 可追溯性
- 所有敏感操作（用户增删、岗位审批、申请审核）均通过 AOP 切面自动记录操作日志
- 日志字段包括：操作人、操作方法、请求参数、IP 地址、操作时间

### 4. 可扩展性
- 后端 RESTful API 统一返回格式：`{ code, message, data }`
- 分页结果统一封装：`{ total, list, pageNum, pageSize }`
- 前端采用 Vue Router 懒加载，按角色拆分路由模块

## 二、业务规则

### 2.1 唯一性约束
| 约束 | 说明 |
|------|------|
| 用户名唯一 | `sys_user.username` 设置 UNIQUE 索引 |
| 同一岗位不可重复投递 | 同一 `(job_id, user_id)` 组合在 `job_application` 中唯一 |

### 2.2 状态流转约束
| 实体 | 状态 | 允许的下一状态 |
|------|------|---------------|
| 岗位(Job) | 0=待审批 | 1=招聘中, 3=已拒绝 |
| 岗位(Job) | 1=招聘中 | 2=已结束 |
| 申请(Application) | 0=待审 | 1=通过, 2=拒绝, 3=取消 |
| 申请(Application) | 1=通过 | — (终态) |
| 申请(Application) | 2=拒绝 | — (终态) |
| 用户(User) | 0=待审批 | 1=正常, 0=禁用 |
| 用户(User) | 1=正常 | 0=禁用 |

### 2.3 业务计算公式
- **岗位薪资** = 单位薪资 × 工时（系统按 BigDecimal 存储，避免浮点精度丢失）
- **岗位申请通过率** = 通过数 / 总申请数 × 100%

### 2.4 配额规则
- 岗位发布时设定招聘名额（quota），当 `count(approved_applications) >= quota` 时自动截止
- 学生投递时前端+后端双重校验配额
