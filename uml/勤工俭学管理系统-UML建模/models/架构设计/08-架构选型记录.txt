# 架构选型记录：勤工俭学管理系统

## 一、整体架构选型

### 备选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A: 单体 MVC** | Spring Boot + Thymeleaf 服务端渲染 | 开发简单，部署单一 | 前后端耦合，难以扩展，用户体验差 |
| **B: 前后分离 MVC（✅ 选用）** | Spring Boot REST API + Vue 3 SPA | 前后独立开发部署，响应快，可扩展 | 需处理跨域、路由，部署多一个 Nginx |
| **C: 微服务** | Spring Cloud + 服务注册/配置中心 | 独立部署、弹性伸缩 | 运维复杂，项目规模不需要 |

### 选型结论：方案 B（前后端分离 MVC）

**选型理由：**
1. 项目面向高校内部使用，并发量有限（千人以下），不需要微服务的分布式能力
2. 前后端分离使得前端 Vue 3 可独立迭代，后端提供统一 RESTful API 可对接未来移动端
3. Docker Compose 三容器编排（Nginx + Spring Boot + MySQL），部署复杂度可控
4. 单体 Spring Boot 避免了服务间通信、分布式事务等额外复杂度

## 二、关键技术选型

### 2.1 认证方案

| 方案 | 描述 | 选用 |
|------|------|:--:|
| Session + Cookie | 服务端存储会话 | ✗ |
| **JWT 无状态 Token** | 客户端存储，服务端验证签名 | ✅ |

**选型理由：** JWT 无需服务端存储会话状态，适合 Docker 横向扩展；Token 内嵌角色信息，减少数据库查询。

### 2.2 前端 UI 框架

| 方案 | 描述 | 选用 |
|------|------|:--:|
| Element Plus | 基于 Vue 3 | ✗ |
| **Ant Design Vue** | 基于 Vue 3，组件更丰富 | ✅ |

**选型理由：** Ant Design Vue 表格、表单、选择器等企业级组件开箱即用，适合管理后台场景。

### 2.3 数据访问层

| 方案 | 描述 | 选用 |
|------|------|:--:|
| JPA/Hibernate | ORM 自动建表 | ✗ |
| **MyBatis + PageHelper** | SQL 手动编写，灵活分页 | ✅ |

**选型理由：** 项目表关系简单但查询复杂（多条件筛选、关联统计），MyBatis 手动 SQL 更灵活可控。

### 2.4 容器化方案

| 方案 | 描述 | 选用 |
|------|------|:--:|
| 手动部署 Jar | 本地 java -jar | ✗ |
| **Docker Compose** | 多容器编排 | ✅ |

**选型理由：** Docker Compose 一键启动 MySQL + 后端 + 前端，消除环境差异，适合演示和交付。
